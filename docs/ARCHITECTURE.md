# 架构说明

## 模块

- `engine/TransformEngine`：共享规则引擎，预览与服务均使用此引擎。
- `engine/MappedText`：记录转换结果的每个 UTF-16 单元对应的原文范围。
- `engine/ChatDraft`：当前输入框的原文、用户编辑、字面片段、稳定后缀选择和近期消息记录。
- `engine/TextUnits`：不可拆分的字符单元，目前为 QQ 内置表情编码。
- `service/ChatTargets`：按应用配置的聊天输入框识别规则（资源 ID、提示文字、布局兜底）。
- `service/ComposerRecognizer`：本次服务运行期间的识别状态（已确认的资源 ID、按布局识别到的 ID）。
- `service/ComposerText`：事件文本还原、组合输入与富文本标记检测。
- `service/MoeAccessibilityService`：事件调度、输入框读取、写回与校验。
- `service/DiagLog`：诊断日志，连续重复的记录合并计数。
- `data/`：配置持久化、预设和有大小限制的文本读取。
- `engine/BidiTools`：独立的 QQ Unicode 昵称与正文保护工具。

## 输入过程

无障碍事件通知间隔为 0。输入、焦点和选区事件立即触发主线程队列任务，
同一轮队列中的多个事件合并，读取输入框的最新快照。窗口内容变化只有文本类变化立即处理；
消息列表和动画产生的其他内容变化按 200 毫秒合并，用于发现焦点切换。

输入时立即执行替换。停顿模式在原文最后变化 120 毫秒后完成消息装饰；
实时模式在非组合输入状态下直接完成装饰。无需等待发送点击，也不操作发送按钮。

输入后最多 1.8 秒内，每 100 毫秒补充检查一次；组合输入时采用 60 毫秒间隔。
离开目标应用后取消任务。目标应用中没有聊天输入框的页面（如会话列表）不进入重试。
输入框暂时不可用或写回失败时先延迟重试三次，
间隔为 40、80、120 毫秒；仍失败且输入风暴未结束时降为 300 毫秒慢速轮询，
直到风暴窗口过去。文本及配置未变化时复用结果，不重复计算或随机抽取。

## 编辑与来源映射

每次变换保留结果到原文的范围映射。收到新文本后，比较共同前后缀，将编辑投影回原文。
在已展开替换词内部的修改扩展到整个来源片段，保留用户编辑后的字面文字。
其他部分继续正常转换，不再暂停整条消息，也不从全局字串猜测并删除后缀。

例如，「我」转换为「本喵」后继续输入「们」，原文仍能恢复为「我们」；
将「谢谢啦」手动删为「谢谢」后，该手动修改保留，新输入的其他文字继续转换。
用户主动修改生成的装饰时，本条消息停止自动补回装饰，但继续执行普通替换。

每条消息固定随机后缀和颜文字。清空输入框后推进顺序选择。
输入框内容与上一条已处理的消息完全不同时，视为新消息，即使清空事件丢失也能正常处理。
近期处理过的消息按文本记录。QQ 切换会话后恢复的草稿若与记录相同，沿用原有映射，
不会再次追加后缀和颜文字。
焦点短暂离开时保留当前编辑器映射；绑定到不同编辑器时重置。
写回成功后把原选区映射到新文本，末尾光标置于生成装饰之前以便继续输入。

## 平台适配与写回

QQ 使用聊天输入框资源 ID（`input`）。QQ 新版本会缩短资源名称，因此资源 ID
不匹配时还接受位于窗口下部的多行输入框，排除搜索框；以此方式识别到的资源 ID
在本次服务运行期间用于后续查找，并写入诊断日志。本次服务运行期间一旦识别到
`input`，说明当前 QQ 版本仍使用该 ID，此后不再按布局识别，避免误选空间评论框等其他输入框。Discord 使用聊天输入框 ID
或消息输入提示，排除搜索框。

定位先刷新已绑定的输入框，失效后再依次查找活跃窗口和目标应用的其他应用窗口：
输入焦点优先，其次按资源 ID 查找，不递归扫描聊天消息列表。输入框不要求持有焦点，
因为部分 ROM 上写回后焦点标志短暂丢失而输入框仍然健在。键盘、系统栏等非应用窗口不查询。

无障碍节点文本为空值时，有两种情况：输入框为空且没有提示文字，或 ROM 隐藏了节点文本。
光标位于开头时按空输入框处理；光标位于文字之后时，使用该输入框文本事件携带的内容。
应用在没有文本事件的情况下替换内容时，该事件内容作废，不会把旧文字写回。

写回前重新检查应用、输入框、原文、选区和组合输入状态。
使用 ACTION_SET_TEXT，读取完整结果校验，不使用剪贴板回退。
检测到组合输入时延后写入。QQ 中包含 `@` 的消息保持原样：@ 成员在输入框中带有附加信息，
无障碍接口无法可靠读取，写回纯文本会使 @ 提醒失效。检测到特殊提及或替换组件的富文本时同样保留原样；
仅显示表情或 QQ 内置表情的替换组件不影响处理，QQ 会根据文本重新生成。

QQ 内置表情在文本中为 U+0014 加一个表情编号字符，编号字符可能是逗号、问号或空格。
所有规则在屏蔽这些编码的副本上匹配，后缀、替换和末尾空白判断都不会拆开表情。

事件类型、标志和目标应用在 `res/xml/accessibility_service_config.xml` 中统一声明，
服务连接时不再覆盖；单元测试检查其中的应用列表与 `ChatTargets` 一致。

Discord 提示和 ID 的适配目前经过逻辑测试，尚无真实客户端节点树验证。
无障碍快照可能不暴露全部组合输入或提及信息；真实客户端兼容性需持续验证。

## Unicode 工具

BidiTools 保持独立，不参与聊天平台自动改字适配。昵称模板只使用 RLI 与 LRI，
因为 QQ 会拒绝含有 LRO 或 RLO 的昵称；
正文保护闭合未结束作用域，并按段落使用 LRI/PDI 包裹正文。
加强模式额外追加三组 PDI/PDF。预览使用本机文本排版，保持现有 QQ 用途。
